# 0.3a — UI kit foundation (spec, 2026-09-25)

1. **Purpose**: one accessible, localised set of primitives every later surface composes from
   (stories: theme switch, four locales, garden/one-hand use). Primary action of the kit: make
   the right thing the easy thing — a `Button`, `Field` or `Dialog` is accessible by default.
2. **States** covered per primitive: rest, hover, focus-visible, active (ripple + press),
   disabled, loading/busy, invalid, selected/checked, open/closed; every state visible in `/kit`.
3. **Layout**: mobile-first; controls 44 px at `md`; toasts full-width at the top on phones,
   a 24 rem stack at the top-end corner from `sm`; dialogs full-width minus 2 rem on phones,
   `max-w-lg` from `sm`, footer buttons stack on phones; landing hero centred, feature cards
   one column → three at `sm`.
4. **Components** (props and contracts in `wiki/ui-kit.md`): Button, LinkButton, IconButton,
   Spinner, Field, Input, Textarea, Select, Checkbox, Switch, Card, Badge, Chip, Alert, Toast,
   Dialog, Skeleton, EmptyState, ThemeToggle, ErrorBoundary; Header, Footer.
5. **i18n**: namespace `ui` — `close`, `dismiss`, `loading`, `optional`, `required`,
   `skipToContent`, `tone.{info,success,caution,danger,error}`; `nav.language`; `errors.{title,
description,retry}`; `notFound.{title,description}`; `home.{eyebrow,explore,featuresHeading,
features.*}`. Hebrew uses noun forms (סגירה, בטעינה) to stay gender-neutral; RTL mirrors
   toast/dialog positions through logical properties and the switch thumb through `rtl:`.
   Cyrillic labels are ≈ 1.3× English — no fixed-width control labels anywhere.
6. **Accessibility**: skip link → `main`; `focus-ring` on every focusable; native `<dialog>`;
   live regions (`status` polite, `alert` for danger) with a spoken tone prefix; every icon
   hidden or labelled; contrast ≥ 4.5:1 text and ≥ 3:1 UI in both themes (table in the design
   system page); reduced motion collapses all motion, spinners slow down.
7. **Privacy cues**: `Switch` is the visibility control pattern (label + description); public
   surfaces will use `Badge` tones for visibility state — no data concerns in the kit itself.
